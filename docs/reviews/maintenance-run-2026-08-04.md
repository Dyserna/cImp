## 1. Contract drift (harness behavior moved)

- **CD-1 [H] MCP calls >2 min auto-background since Claude Code 2.1.212.** Claude gets a task id immediately; the result arrives later as a notification. Directly hits `offload_task`, `offload_batch`, the audit tools, and long graph indexing. Tunable: `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS` (0 disables). **Suggest:** set the env var in cImp's Claude spawn env (spawn-baked → needs a `spawn_inject_sig` entry + Settings restart hint), or live-verify that a >2-min offload survives backgrounding end-to-end. Related: per-server `request_timeout_ms` was silently ignored before 2.1.206.
- **CD-2 [H] PreCompact stdout is NOT injected** (docs now explicit: stdout → debug log; injection requires `hookSpecificOutput.additionalContext`; input payload has no `trigger`/`custom_instructions`). cImp already emits the `additionalContext` shape, so the implementation is likely fine — but this contract remains the still-unverified **D0 spike**, and docs corroboration is weak. **Suggest:** run the D0 recipe; also note the new `PostCompact` event exists.
- **CD-3 [M] Permission-prompt text is now runtime-composed** from remappable chord labels (verified by disassembling 2.1.221: renders `Esc to cancel · Tab to amend` on default Windows config, but a `~/.claude/keybindings.json` rebind changes it, the amend segment is conditional, and an `… to explain` segment can append). **Suggest:** relax the V2-03 matcher (match `to cancel` / non-anchored `Esc to cancel`), and see NC-2 for the real fix.
- **CD-4 [M] `--settings` overlay changes:** files >2 MiB hard-fail at startup (2.1.214); plugins-via-`--settings` was broken 2.1.181–2.1.214; single-segment permission globs like `Edit(src/**)` now match only `<cwd>/src` depth (2.1.214, breaking); `Write(path)`/`Glob(path)`/`NotebookEdit(path)` rules now warn — use `Edit(path)`/`Read(path)`. **Suggest:** audit the generated overlay + any permission rules cImp writes; assert overlay size at build time.
- **CD-5 [M] Transcript JSONL:** docs now explicitly withdraw format stability ("can break on any release"). In-window: assistant messages gained an effort field (2.1.212); `SessionStart.source` gained `"fork"` (unknown-variant risk in any exhaustive match); token/cost **double-counting on streamed responses fixed in 2.1.214** — cImp usage data recorded before that boundary is inflated; 2.1.211 fixed reopened background sessions reusing a session id (relevant to session-keyed state). `Task`/`Agent` both still appear — keep matching both. `subagents/*.jsonl` remains undocumented (cImp's own forward-only contract).
- **CD-6 [M] MCP spec revision 2026-07-28** (verified from modelcontextprotocol.io): `Mcp-Session-Id` header **removed**, `Mcp-Method`/`Mcp-Name` headers now required on client POSTs, legacy handshake gone in "modern-only" servers (legacy clients get 400, no fall-forward; error `-32022`). cImp's `mcp_host.rs` hardcodes `protocolVersion: "2025-06-18"` and re-sends `Mcp-Session-Id` — fine against dual-era servers today, breaks against modern-only ones eventually. No EOL policy for old revisions exists. **Suggest:** make `protocolVersion` negotiable, tolerate `-32022`, and treat session-header absence as normal; low urgency, real direction.
- **CD-7 [M] OpenCode 1.18.1 → 1.18.13 upgrade tripwires:** (a) MCP client SDK v2 landed in 1.18.8 and **broke legacy MCP servers**, same-day compat restore in 1.18.9, SSE-reconnect fix in 1.18.11 — smoke-test `cimp-offload` (Streamable HTTP) against 1.18.13 before trusting an upgrade; (b) `subagent_depth` now defaults to 1 (nested subagents blocked) since 1.18.2 — set 2 in the injected config if nesting is relied on; (c) repo moved `sst/opencode` → **`anomalyco/opencode`** (301 redirect works; update any hardcoded URLs/docs). Plugin hooks themselves: **proven byte-identical** since 2026-06-01 (`chat.message`, `tool.execute.before/after` all carry `sessionID`) — no drift. Docs trap: the plugins page's "Events" list omits `chat.message` entirely; don't conclude removal from it.
- **CD-8 [L] llama.cpp `--jinja` is now default-enabled** — cImp's missing-`--jinja` warning (`offload/server.rs`) is a false positive on current builds. **Suggest:** soften/version-gate the warning. Also `--mlock`/`--mmap`/`--dio` deprecated in favor of `--load-mode`.
- **CD-9 [H-verify, cheap] llama.cpp `/props` `n_ctx` semantics.** Current README describes `n_ctx` as global-with-slots-inheriting and documents `--kv-unified` as *default-enabled when slots are auto* — both in tension with cImp's empirically-confirmed per-slot reading (`server.rs` deliberately does not divide by `parallel`). If unified KV now reports the full window while slots share it, cImp **over-budgets context silently**. **Suggest:** one curl against a live `-np 2` server settles it; do this before any llama.cpp rebuild. (All llama.cpp fields cImp reads are `Option`+default — renames degrade silently, which is resilience but also drift-blindness.)
- **CD-10 [L] ddg MCP server:** v0.5.0 made private/loopback URLs in `fetch_content` require `DDG_ALLOW_PRIVATE_URLS=1` (breaking if relied on); v0.5.0+ adds curl_cffi TLS-impersonation fallback for DDG blocking; current 0.6.1. context7: current README confirms `resolve-library-id`/`query-docs` (matches cImp), free tier needs no key; July 30 release moved auth to standard `Authorization: Bearer` — check nothing sends the old `CONTEXT7_API_KEY` header.

## 3. New capabilities worth adopting (feature-ideas)

- **NC-1 [H] MCP session identity is finally closable on the Claude side:** register a `PreToolUse` hook matched to `mcp__cimp-offload__*` — it fires right before each MCP call carrying `session_id`, `prompt_id`, `tool_use_id`, and `tool_input`; the loopback correlates by tool name + args. Closes the V10 residual (same-agent tabs sharing memory scope). OpenCode side already carries `sessionID`+`callID` in `tool.execute.*` — exact-session scoping is implementable **today on both harnesses**. (Definitive negative on the env-var route: MCP servers are spawned once per instance, no per-session env, `CLAUDE_CODE_CHILD_SESSION` explicitly unset for them.)
- **NC-2 [M] `PermissionRequest` / `PermissionDenied` hook events** — a structured, documented replacement for the TUI permission-prompt regex (CD-3). Hook count went ~9 → 31; also notable: `SubagentStart/Stop`, `PostToolUseFailure`, `PostToolBatch`, `FileChanged`, `ConfigChange`, `PostCompact`, `Elicitation`. **Suggest:** adopt PermissionRequest as primary detection, demote the regex to fallback.
- **NC-3 [M] Statusline `context_window` block** (`total_input_tokens`, `context_window_size`, `used/remaining_percentage`, cache split) + `session_name`/`agent`/`effort`/`fast_mode` — the context bar and per-turn cache stats can ride the same push that feeds the quota widget; no second data path.
- **NC-4 [M] MCP channels** (`claude/channel` capability + `--channels`): servers can push messages **into** a live session — an inbound path cImp never had. Candidate for out-of-band offload-completion notices; pairs with CD-1's auto-backgrounding. Also MCP elicitation (mid-call structured input; blocked calls exempt from auto-backgrounding).
- **NC-5 [M] OpenCode `POST /mcp`** — register an MCP server at runtime; could replace the config-rewrite-plus-restart-tab live-reload flow (and the tools/list-caching pain). Plus `POST /session/:id/prompt_async`, V2 plugin API (additive, v1 not deprecated), `permission.task` subagent gating, experimental env flags, Claude-interop kill switches (`OPENCODE_DISABLE_CLAUDE_CODE*`).
- **NC-6 [L] `--forward-subagent-text` / env equivalent** (2.1.211, depth-2+ in 2.1.219, keyed by spawning `tool_use` id) — a documented alternative to the fragile `subagents/*.jsonl` tap if it ever breaks.
- **NC-7 [L] Subagent budget/cost controls:** `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` (200), `MAX_CONCURRENT_SUBAGENTS` (20), `MAX_SUBAGENT_SPAWN_DEPTH` (3 since 2.1.219), `--max-budget-usd` now halts background subagents. Note: **the built-in Explore agent inherits the session model since 2.1.198** (was Haiku) — fan-out is costlier than older guidance assumed.
- **NC-8 [M] Model/engine candidates:** offload — **Qwen3-Coder-Next** (80B-A3B, same ~3B active footprint as current Qwen3.6-35B-A3B, coding-agent-tuned, official GGUF; verify chat-template/tool-calls against our llama.cpp first). STT — A/B **`ggml-large-v3-turbo`** (~1.5 GB, typically beats `small` on accuracy *and* speed; cost is size not latency); **Parakeet** support landed in whisper.cpp v1.9.0 (>2000 RTFx class) but our vendored whisper.cpp is 1.8.3 — needs a whisper-rs-sys bump first. Embeddings — no forced move (Qwen3-Embedding line still current); Jina v4 GGUF worth a look someday. Kokoro — v1.0 still latest, nothing to do. Note: `chat_template_kwargs.enable_thinking` is Qwen-specific — revisit on any non-Qwen swap.
