# SHA-256 checksums for the model blobs bundled into the portable releases.
#
# Format: one `<sha256>  <filename>` per line (paths relative to models/).
# Matches `sha256sum`'s output so it pipes into `sha256sum -c` if desired.
#
# The blobs themselves are NOT in git. They used to be Git-LFS files, but
# CI pulls exhausted the LFS bandwidth quota; they are now assets on the
# `models-v1` GitHub release (our own mirror, so the project doesn't go
# dark if upstream HuggingFace moves or rate-limits — and asset downloads
# are unmetered). This file is the manifest that drives
# scripts/fetch-models.ps1 / .sh (download + verify; also run by the
# release workflow) and scripts/publish-models-release.ps1 (maintainer
# upload).
#

# uncommenting them before the assets exist on the `models-v1` release turns

# Deploy checklist (V32 Phase C follow-up):
#   1. Accept the Llama licence and pull
#      https://huggingface.co/meta-llama/Llama-Prompt-Guard-2-22M

#   2. Export to ONNX (opset 14+, dynamic batch + sequence axes, int64
#      `input_ids`/`attention_mask`; the classifier accepts a 1-logit or
#      2-logit head — see offload/detection/classifier.rs::score_from_logits)
#      and copy the repo's `tokenizer.json` unchanged.
#   3. Place them at models/promptguard2-22m/{model.onnx,tokenizer.json},
#      record the real SHA-256s here, uncomment.
#   4. Upload with scripts/publish-models-release.ps1 (assets are flat: the
#      files land on the release as `model.onnx` / `tokenizer.json`, which
#      COLLIDE with any other model exported under those generic names —
#      rename them to `promptguard2-22m.onnx` / `promptguard2-22m-tokenizer.json`
#      on the release, or teach the scripts a per-entry asset-name column,
#      before publishing).
#   5. Add the paths to the `models cache` allowlist and the staging `cp`
#      lines in .github/workflows/release.yml.
#   6. NOTICE: Prompt Guard 2 ships under the Llama 4 Community Licence —
#      add its attribution before the assets go into a release zip.
#
